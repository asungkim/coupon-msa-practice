# 백엔드 작업 원칙

## 테스트

### 테스트 전략

- 테스트 피라미드를 따른다: 단위 테스트 > 슬라이스 테스트 > 통합 테스트.
- 가능한 한 가장 좁은 테스트 범위를 먼저 선택한다.
- 테스트는 빠르고, 독립적이고, 순서 비의존적이어야 한다.
- 테스트는 구현 세부가 아니라 동작을 검증해야 한다.
- 과제 특성상 수식, 예외, 검색 조건처럼 깨지기 쉬운 규칙을 우선 테스트한다.

### TDD 워크플로우

1. 테스트 작성 전에 먼저 공개 인터페이스와 우선 검증할 행동 목록을 정리한다.
2. 가장 작은 성공 경로를 증명하는 tracer bullet 테스트를 먼저 작성한다.
3. 실패하는 테스트 하나를 작성한다.
4. 현재 테스트를 통과시키는 최소 구현만 추가한다.
5. 모든 테스트가 green인 상태에서만 리팩터링한다.
6. 회귀 여부와 문서 정합성을 검증한 뒤 다음 행동으로 넘어간다.

- 새 기능, 버그 수정, 리팩터링, API 추가는 기본적으로 이 순서를 따른다.
- 모든 테스트를 먼저 몰아서 작성한 뒤 구현을 한꺼번에 진행하는 horizontal slicing을 금지한다.
- TDD는 `한 행동 -> 한 실패 테스트 -> 최소 구현 -> green -> 리팩터링`의 세로 슬라이스로 진행한다.
- 테스트가 과도하게 복잡해지면 구현을 더 작은 단위로 분해할지 먼저 검토한다.
- 아직 작성하지 않은 테스트를 미리 대비한 일반화나 추상화를 금지한다.
- RED 상태에서는 리팩터링하지 않는다.

### TDD 사이클 체크리스트

- 이 테스트는 구현이 아니라 행동을 검증하는가?
- public interface만 사용하고 있는가?
- 내부 리팩터링 후에도 살아남을 테스트인가?
- 이번 테스트를 위한 최소 코드만 작성했는가?
- 미래 요구사항을 미리 구현하지 않았는가?

### 테스트 종류별 규칙

#### 단위 테스트

- 대상: 서비스, 계산기, 유틸, 순수 비즈니스 로직
- 도구: JUnit 5 + AssertJ + Mockito-Kotlin
- Spring Context 없이 실행하는 것을 기본으로 한다.
- 의존성은 `mock()`, `whenever()`, 생성자 주입 기반으로 구성한다.
- `@InjectMocks`보다 명시적 객체 생성을 우선한다.

#### 웹 레이어 테스트

- 대상: 컨트롤러, 요청/응답 매핑, HTTP 상태 코드, JSON 응답, 예외 응답 형식
- 도구: `@WebMvcTest` + `MockMvc`
- 서비스 계층은 `@MockBean`으로 격리한다.
- JSON 응답 검증은 `jsonPath`를 사용한다.

#### 영속성 테스트

- 대상: JPA 매핑, repository 쿼리, 검색/정렬/필터 조합
- 도구: `@DataJpaTest`
- 기본은 H2로 검증한다.
- DB 차이로 인해 실제 DB 검증이 필요한 경우는 개선 과제로 분리한다.

#### 통합 테스트

- 대상: 애플리케이션 흐름 전체, 예외 변환, 응답 형식, 스케줄러 연계 흐름
- 도구: `@SpringBootTest` + `@AutoConfigureMockMvc` + `@ActiveProfiles("test")`
- 외부 API는 실제 호출하지 않고 mock server 또는 stub으로 격리한다.

### 테스트 작성 규칙

- 테스트 클래스 이름은 `*Test` 접미사를 사용한다.
- 테스트는 Arrange-Act-Assert 패턴으로 작성한다.
- 테스트 이름은 동작 중심으로 구체적으로 작성한다.
- 필요 시 `@DisplayName`으로 의도를 명확히 드러낸다.
- 예외 검증은 `assertThrows` 또는 AssertJ 예외 assertion을 사용한다.
- 변형 입력 검증에는 `@ParameterizedTest`를 우선 검토한다.
- 반복되는 테스트 데이터는 fixture 함수 또는 builder로 추출한다.

### 검증 명령

- 로컬 테스트: `cd backend && ./gradlew test`
- 애플리케이션 실행: `cd backend && ./gradlew bootRun`
- 테스트 프로파일 실행: `cd backend && ./gradlew bootRun --args='--spring.profiles.active=test'`
