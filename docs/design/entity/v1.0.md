# 선착순 쿠폰 발급 시스템 엔티티 스펙 v1.0

## 공통 사항

- PK는 `Long` 타입, `IDENTITY` 전략 (auto-increment)
- BaseEntity 없이 각 엔티티에 필요한 필드만 직접 정의한다
- Soft Delete 미사용 (ddl-auto: create-drop 환경)

---

## 1. 유저

### User

- id (Long, PK, auto-increment)
- email (String, NOT NULL)
- name (String, NOT NULL)
- point (Long, NOT NULL, default 0)

**비고:**

- 포인트는 쿠폰 발급 시 차감된다
- `point`는 음수가 될 수 없다
- 유저 생성, 포인트 충전은 셋업 API로 제공 (동시성 문제 범위 밖)

---

## 2. 쿠폰

### Coupon

- id (Long, PK, auto-increment)
- name (String, NOT NULL)
- description (String, nullable)
- pointCost (Integer, NOT NULL)
- totalQuantity (Integer, NOT NULL)
- remainingQuantity (Integer, NOT NULL)
- startDate (LocalDateTime, NOT NULL)
- endDate (LocalDateTime, NOT NULL)

**비즈니스 규칙:**

- 생성 시 `remainingQuantity = totalQuantity`로 초기화
- 발급 가능 조건: `remainingQuantity > 0` AND `now` ∈ `[startDate, endDate]`
- `remainingQuantity`는 발급 시 1씩 감소 → **동시성 제어 핵심 대상**

---

## 3. 쿠폰 발급

### CouponIssue

- id (Long, PK, auto-increment)
- userId (Long, NOT NULL, FK → User)
- couponId (Long, NOT NULL, FK → Coupon)
- status (IssueStatus, NOT NULL)
- issuedAt (LocalDateTime, NOT NULL)

**ENUM:**

```java
enum IssueStatus {
    ISSUED,   // 발급 완료
    USED,     // 사용 완료 (v1.0 미사용)
    EXPIRED   // 만료 (v1.0 미사용)
}
```

**인덱스:**

- `uk_coupon_issue_user_coupon` UNIQUE on (userId, couponId) — 1인 1매 중복 방지

**비고:**

- v1.0에서는 `ISSUED` 상태만 사용
- userId + couponId 유니크 제약으로 DB 레벨에서 중복 발급 차단
