# Phase 3. 테스트 고도화 + DB 락 한계 돌파

## 🔹 Epic: 테스트 환경 표준화

> 문제: 현재 로컬 환경에서 CPU/메모리 제한 없이 테스트 → 결과 일관성 부족
> 문제: WebClient 직접 호출 방식 → 테스트 클라이언트 자체가 병목 가능

- ⚪ Docker 기반 서버 환경 구성 (CPU/메모리 제한으로 일관된 테스트 조건)
- ⚪ 전문 부하 테스트 도구 도입 (k6 or Gatling)
- ⚪ 셋업(유저/쿠폰 생성)과 발급 구간 분리 측정
- ⚪ TPS, p99 레이턴시, 에러율 등 정밀 메트릭 수집

## 🔹 Epic: 정밀 벤치마크

> 목표: 원자적 UPDATE vs 비관적 락을 통제된 환경에서 정확히 비교

- ⚪ 동일 리소스 제한 하에서 원자적 UPDATE vs 비관적 락 성능 비교
- ⚪ 데이터 규모별 테스트 (기존 발급 건수 1만/10만건일 때 성능 변화)
- ⚪ HikariCP 10개 제약 하에서 최적 전략 결정
- ⚪ 벤치마크 결과 정리 및 전략 확정

## 🔹 Epic: DB 락 한계 돌파 (외부 인프라)

> 문제: DB row lock이 병목 — 서버를 늘려도 같은 row 경합은 해소 불가
> 목표: DB 접근 전에 빠른 계층에서 재고를 차감하여 DB 부하 최소화

- ⚪ Redis 재고 차감 도입 (DECR or Lua script로 원자적 처리)
- ⚪ Redis 통과 → DB 확정 2단계 구조 설계
- ⚪ Redis 장애 시 fallback 전략 (서킷브레이커 등)
- ⚪ 부하 테스트 — DB 락만 vs Redis + DB 성능 비교
- ⚪ 최종 아키텍처 정리
